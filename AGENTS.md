# Agent Guidelines for `ProcessWire\React` (`Totoglu\React`)

Architecture overview: [docs/ARCHITECTURE.md](./docs/ARCHITECTURE.md) | Chapter index: [docs/README.md](./docs/README.md).

## Architectural Invariants

1. **Boot, Optional Hub & Autoloading (`WireClassLoader`):**
   - `React` (`singular => true, autoload => true`) extends `ProcessWire\WireData` (`implements Module, ConfigurableModule`), requires `['PHP>=8.4', 'ProcessWire>=3.0.271', 'Inertia']`, defines **no admin page**, delegates HTTP endpoints, translations, ProcessWire hooks, and the classic `rwControl` Inputfield bridge to `ReactGatewayRouter` (`$react->gateway()`), `TranslationCatalogService` (`$react->i18n()`), `FieldIntegrationHooks` (`$react->hooks()`), `ReactControlRegistry` (`$react->controls()`), and `SignedTokenCodec` (`$react->tokenCodec()`), and registers `Totoglu\React` -> `__DIR__ . '/src/'` **once** inside `React::__construct()`.
   - `React::init()` registers the lightweight `/_react/*` URL hooks and always-on data hooks (`FieldIntegrationHooks::registerDataHooks()`) and gates admin UI hooks (`FieldIntegrationHooks::registerAdminHooks()`) via `shouldRegisterFieldHooks()` (registering lazily in `ready()` on admin pages and `gateway()` on `/_react/*` routes so frontend requests incur zero admin field-hook overhead while `autoload => true` avoids `ModulesLoader` dependency warnings).
   - `ProcessReactWorkspace` (`extends WorkspaceLauncherProcess` -> `ProcessReact`, `autoload => false`) lives in the same directory as an **optional** `Process` module (`requires => [..., 'React']`, not listed in `React`'s `installs`) mounting `Admin > Workspace` (`/processwire/workspace/`) only when installed.
   - Never add `class_exists` / `trait_exists` / `interface_exists` / `require_once` guards or duplicate `addNamespace()` calls in `.module.php` or `src/` files; `WireClassLoader` resolves all `Totoglu\React\*` classes and companion `.module.php` modules natively.
   - Zero dependency on downstream consumer modules; verify with `LayeringTest.php`.
   - `React` installs all 15 companion modules: `MarkupReactTable` (`singular => false`), `MarkupReactCards` (`singular => false`), `MarkupReactTab` (`singular => false`), `InputfieldReactKeyValue`, `InputfieldReactCondition`, `InputfieldReactLink`, `InputfieldReactIcon`, `InputfieldReactM2O`, `InputfieldReactM2M`, `InputfieldReactO2M`, `InputfieldReactM2A`, `InputfieldTiptap`, `TextformatterTiptapMiniBlocks`, `InputfieldReactFile`, `InputfieldReactImage`.
   - Module versions live solely in `React::getModuleInfo()['version']` and companion `*.info.php` `'version'` entries (no `VERSION` class constants): when a companion submodule changes, bump both that submodule's version (`companion <= main`) and `React::getModuleInfo()['version']`; when no companion submodule changed, bump only `React::getModuleInfo()['version']`.

2. **Pull-Discovery (`reactCapabilities`) & Zero Cold-Boot Overhead:**
   - Downstream modules stay `'autoload' => false` and declare `'reactCapabilities' => [...]` (subset of `React::CAPABILITIES`: `['workspace', 'icons', 'commandSearch', 'providers', 'relations', 'linkResolvers', 'media', 'viewportModes']`) in `static getModuleInfo(): array`.
   - `React` reads `Modules::getModuleInfo('*')` (`moduleInfoCache`) via `discoverCapabilityModules()` without loading module PHP files, and lazily pulls installed modules via `pullCapabilities($capability)` (`getModule($name, ['noPermissionCheck' => true, 'noInstall' => true, 'noThrow' => true])`) before resolving `workspaces()`, `widgets()`, `commandSearch()`, `providers()`, `relations()`, `resolveCustomLink()`/`linkResolverTypes()`, `media()`, `getRegisteredViewportModes()`, or `IconManager::generateAdminCss()` (guarded by `rw-cap-sig:` in `VectorIcons.css` so `ensureAdminCss()` stays O(1) on cached admin loads).
   - Downstream modules register workspaces and widgets via `React::deferModuleRegistration($this, $workspaceRegistrar, $widgetRegistrar)`, custom shell layouts via `React::deferShellLayoutRegistration($this, $registrar)`, command palette search via `React::deferCommandSearchRegistration($this, $registrar)`, viewport data providers via `React::deferProviderRegistration($this, $registrar)`, relation resources via `React::deferRelationRegistration($this, $registrar)`, link resolvers via `React::deferLinkResolverRegistration($this, $registrar)`, entity media hosts via `React::deferMediaHostRegistration($this, $registrar)`, and pluggable viewport modes via `React::deferViewportModeRegistration($this, $registrar)` so registries, `statsCallback`, and `dataCallback` never run on frontend or unrelated requests.
   - `buildInertiaSharedContext()` passes `$includeStats = false` and `$accessibleWidgets = null` so widget data and workspace stat queries execute only when `/processwire/workspace/` is rendered.

3. **Extendable Base Classes (`Totoglu\React\Inertia` & `Viewport`):**
   - **`ProcessReact`** (`extends ProcessInertia`, uses `InteractWithReact`): Dual-context base class for downstream admin `Process` controllers (`ProcessWire*` and `ProcessReactWorkspace`). When opened via `Setup > <Module>` (`shellMode === 'admin'`), executes natively through `wire/core/admin.php` -> `ProcessController::execute()` via `EmbeddedAdminPageResponse` inside whichever `AdminTheme` is active (`AdminThemeUikit`, `AdminThemeDefault`, `AdminThemeReno`, or custom `AdminTheme`) with CSS `revert-layer` cascade isolation; when opened via `Admin > Workspace` (`?ws=1`, `shellMode === 'workspace'`), renders the standalone full-screen Workspace shell (`views/admin.php`), preserving `--pw-*` color scheme tokens and `OnceProp` `i18n` catalogs across both contexts.
   - **`InputfieldReact`** (`extends InputfieldInertia`, uses `InteractWithReactTranslations`): Base class for dual-mode React Inputfields working both as classic ProcessWire form islands (`<input type="hidden">` sync) and as `SchemaForm` / Inertia props (`toInertiaProp()`); every island renderer MUST wrap prop assembly + `PropResolver::resolveValue()` inside `Inertia::withoutEntityEncoding()`.
   - **React Hook Order & `RangeField` Sub-Components:** Never place `useState`/`useEffect` after conditional early returns (`RangeField` delegates `colspan`/`single`/`dual` sliders to child components to prevent React Error #310 on dynamic `value` transitions).
   - **`MarkupReactViewport`** (`extends MarkupInertia`): Base class for `MarkupReactTable`, `MarkupReactCards`, and downstream viewports.

4. **Security & Signed Gateways (`/_react/*`):**
   - `SignedTokenCodec` derives domain-separated HMAC-SHA256 subkeys from `$config->userAuthSalt` for `stateToken` (`/_react/viewport`), `presenceToken` (`/_react/presence`), `relationToken` (`/_react/relation`), `mediaToken` (`/_react/media`), and `tiptapToken` (`/_react/tiptap`), bound to `$user->id` (`uid`) and expiring after 24h (`iat`).
   - All mutating actions across `/_react/viewport`, `/_react/workspace-prefs`, `/_react/presence`, `/_react/relation`, `/_react/media`, and `/_react/tiptap` reject guest users (`403`) and validate `$session->CSRF` (`verifyRequestCsrf()`). `/_react/presence` additionally verifies `presenceToken` (issued via `$react->issuePresenceToken()`) and `canMarkSaved` authorization before mutating presence state.
   - `UploadedFileValidator`, `MediaGateway`, and `TiptapMediaLinkGateway` enforce field-level/page-level `editable()` RBAC, `finfo_file` MIME verification, temp-directory staging before moving validated uploads, `maxFiles` and raster pixel bounds, and DOM-based active SVG blocking; `InputfieldTiptap` (`TiptapPresetCatalog`, `TiptapAssetResolver`, `TiptapConfigFormBuilder`, `TiptapContentPolicy`, `DomFragmentHelper`) loads modular Tiptap bundles (`TiptapCore.css` + `TiptapCore.js`, optional `TiptapEditor.js` / `TiptapCanvas.js` / `TiptapBlocks.js`, and strictly lazy `TiptapDialogs.js`) with zero shared `ReactInertia-*.js` chunks, and enforces `MarkupHTMLPurifier` + deterministic DOM allowlist fallback and `Languages::editable()`.
   - `/_react/icons` (`IconManager`) is strictly `GET`/`HEAD` (`405` on `POST`) with bounded query/hydration inputs over static `dist/vector-icons.json` geometry.

5. **Centralized Vector Icon Subsystem (`IconManager` & `InputfieldReactIcon`):**
   - Build-time `vectorIconCatalogPlugin()` in `vite.config.ts` emits `dist/vector-icons.json` (`5,491` outline + `1,054` filled = `6,545` icons, `41` categories, popular list, tags, and shorthand aliases in `faAliases.ts`), while `coreUiIcons.ts` preloads synchronous core UI icon tuples for `<DynamicIcon />` so `dist/ReactIcons.js` stays `< 16 kB` and `dist/ReactInertia.js` stays `< 700 kB` with zero secondary icon library dependencies.
   - Never expose external icon library brand names in user-facing labels, placeholders, descriptions, validation errors, or documentation.
   - Admin Template/Field hooks (`hookAdminIcon*` in `FieldIntegrationHooks`) inject `vectorIcon` (`Vector Icon`) non-destructively below ProcessWire's native Icon field (`showIf="vectorIcon=''"`) and generate `site/assets/vector-icons/VectorIcons.css` `mask-image` rules.

6. **Strict Core vs. Companion Submodule Asset Isolation (`resources/build-bundles.mjs`), Typed SDK (`@pw/react/*`) & Delta CSS:**
   - Downstream extension modules consume `window.ReactWorkspaceRuntime` through the typed `@pw/react/*` SDK subpaths (`core`, `ui`, `layout`, `viewports`, `fields`, `hooks`, `dnd`, `grid`, `calendar`, `optional`) mapped by root `vite.module.ts` (`defineWireModuleConfig(import.meta.dirname, { jsx: 'automatic', tailwind: true })`), keeping zero React/Inertia runtime duplication or `runtime.ts` copy-paste shims in sibling modules. `@pw/react/hooks` exports `useKeyboardShortcuts`, `KeyboardShortcutsProvider`, `useRegisteredKeyboardShortcuts`, and `formatShortcutKeys` so module workspaces and forms participate in the global shortcut registry and help dialog; `CliBox` supports optional `wrap`; and `MarkupReactViewport` lazy-loads mode-specific `viewStyles` alongside `viewScripts` for optional adapters (`ReactGrid`, `ReactDnd`, `ReactCalendar`).
   - `dist/ReactInertia.js` (`< 700 kB`), `dist/ReactInertia.css`, `dist/ReactViewports.js`, and `dist/SchemaForm.js` (`< 220 kB`) must never bundle companion-submodule UI or CSS (`MarkupReactTable`, `MarkupReactCards`, `MarkupReactTab`, `InputfieldReactKeyValue`, `InputfieldReactIcon`, `InputfieldReactLink`, `InputfieldReactFile`, `InputfieldReactImage`, `InputfieldReactM2O`/`M2M`/`O2M`/`M2A`, `InputfieldTiptap`), nor scan sibling modules in `ReactInertia.css`. Each consumer module compiles its own lightweight utility delta stylesheet importing `site/modules/React/resources/css/module-delta.css`, and `resources/tailwind-layers.mjs` partitions `@layer utilities` across both `ReactInertia.css` and downstream delta stylesheets (including `[dir=rtl]`, `[dir=ltr]`, `:is(`, `.dark-theme`, recursive nested `@media`/`@supports`, and ordered `@container-*` rules) into deterministic sub-layers so downstream unprefixed utilities never override responsive/state variants in `ReactInertia.css`.
   - Every companion module's `getModuleScriptAssets()` / `getModuleStyleAssets()` enqueues only its own self-contained bundle(s) (`MarkupReactTable.js`, `MarkupReactCards.js`, `MarkupReactTab.js`, `InputfieldReactKeyValue.js`, `InputfieldReactIcon.js`, `InputfieldReactLink.js`, `ReactMedia.js` + `ReactMedia.css` + `InputfieldReactFile.js`/`InputfieldReactImage.js`, `InputfieldReactRelation.js`, `Tiptap*.js` + `TiptapCore.css`) compiled by `node resources/build-bundles.mjs` (`VITE_BUILD_ENTRY`), with optional lazy form chunks (`ReactCalendar.js` + `ReactCalendar.css`, `ReactExtraFields.js`) prefetched on demand by `SchemaForm` (and standalone classic `rwControl` bridges routing extra controls to `ReactWorkspace/ExtraFieldControl` in `ReactExtraFields.js` without loading `SchemaForm.js`, vs core schema controls to `ReactWorkspace/FieldControl` in `SchemaForm.js`), and zero `ReactInertia-*.js` shared chunks or `*.style.js` leftovers.
   - Core runtime helpers (`loadRuntimeScript`, `loadRuntimeStyle`, `preloadRuntimeScript`, `ensureMediaStyleLoaded`) and domain-agnostic CSS contracts (`[data-rw-prose-root]`, `[data-rw-table]`, `[data-rw-card-tabs="above"]`, `[data-rw-meta-*]`, `[data-rw-ref-*]`, `[data-rw-rev-table]`, `[data-rw-diff-pill]`) keep optional hub discovery (`workspace.launcherComponent`), `ReactTiptapRuntime.ensureBundles()`, media styles, and empty `VectorIcons.css` gating decoupled from core requests; `useSchemaFormContext()` must never trigger `ensureFieldsLoaded()`. `SchemaMarkupNode` handles `[data-copy-text]` clicks safely with `1500ms` `data-copied="1"` + polite `aria-live` feedback even when `navigator.clipboard` is unavailable.

7. **Centralized Theme Management (`Totoglu\React\Theme\ThemeManager`) & Multi-Shell Navigation (`ShellLayoutRegistry`):**
   - `$react->theme()` resolves site-wide defaults (`themePreset`, `themeCustomTokens` stored in `React` module config) and per-user overrides (`themeMode`, `themePreset`) stored in `WorkspacePreferenceStore` (`{user-id}.json`), providing distinct `--sidebar*` surface tokens alongside `--masthead*` tokens in `ThemePreset`. `ThemeTokenParser` supports `:root`, `.dark`, `@media (prefers-color-scheme: dark) { :root { ... } }`, and dark-only tokens. Compiled `light-dark()` tokens flow uniformly to standalone workspaces (`views/admin.php` `<style id="rw-theme-tokens">`), embedded admin panels (`AdminTheme::addExtraMarkup('head', ...)`), Inputfield islands, and portaled dialogs across all modules.
   - `ShellLayout` enum (`Topbar = 'topbar'`, `Sidebar = 'sidebar'`) and `ShellLayoutRegistry` (`$react->shellLayouts()`) coordinate multi-shell navigation with `React::resolveEffectiveShellLayout()` precedence (per-user `{user-id}.json` override > `defaultShellLayout` module config > `'topbar'`). Authenticated users switch personal mode, color presets, panel layout (`topbar` / `sidebar` / reset to site default), and collapsed rail state (`sidebarCollapsed`, toggled via button or `Cmd/Ctrl+B`) from `UserAccountMenu` via `/_react/workspace-prefs` (`set_theme_mode`, `set_theme_preset`, `set_shell_layout`, `set_sidebar_collapsed`). Custom layouts register in PHP via `React::deferShellLayoutRegistration()` and on the client via `@pw/react/layout`'s `registerShellLayout()` (`TopbarShellLayout`, `SidebarShellLayout`, `ModuleSwitcher`, `useShellLayout`).

8. **Multi-Language (`i18n`) Synchronization:**
   - Static UI catalogs declared in `___translations()` and PHP `$this->_()` / `__()` strings resolve strictly through ProcessWire's native `LanguageTranslator` (`Setup > Languages`, with zero runtime CSV file fallback); `languages/{en,tr,de,fr,es,ru}.csv` serve as `LanguagePorter::exportCsv` import packs that must stay row-for-row and MD5-identical (verified by `ReactTranslationsTest.php`).
   - Every PHP file under `tests/` MUST start with `<?php // __(file-not-translatable)` on line 1.

9. **Verification Commands (Run Sequentially):**
   - Cold CLI boot: `php vendor/bin/wire version --json`
   - PHPStan Level 8: `./vendor/bin/phpstan analyse -c site/modules/React/phpstan.neon --no-progress --memory-limit=1G`
   - TypeScript & Vite build: `npm --prefix site/modules/React run build`
   - Vitest unit tests: `npm --prefix site/modules/React run test:unit`
   - Pest PHP suite: `php vendor/bin/wire test site/modules/React/tests --json`
   - Playwright E2E & WCAG 2.1 AA suite: `php vendor/bin/wire test:e2e --module=React --json`
